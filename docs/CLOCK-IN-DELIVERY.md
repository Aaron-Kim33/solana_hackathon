- FAQ: 초안은 수정 가능하나 최종 제출 동의 후 수정 불가. 최종 제출 직전 링크·APK·커밋 확인.

## 승인된 제품 방향

핵심: 계속 때릴지, 5초 후 사라질 목재를 회수할지 선택하는 모바일 성장 게임.

1. 기존 게임을 보존하면서 메인 입력을 서버 검증 경로에 연결. 타격 시각 피드백은 즉시, 재화는 서버 확정 후.
2. 첫 5분 UX/아트, 한손 조작, 한국어/영어, 실제 신규 사용자 피드백 우선.
3. 확정형 외형 상품 하나의 구매→검증→한 번 지급→복구→착용 흐름. 실제 결제 활성화는 별도 승인과 검증 필요.
4. SGT 전용 외형/배지 또는 공정 도전은 여력이 있을 때. SGT는 mint 기준 중복 방지, 인간/매크로 방지의 완전한 증명이 아님.
5. 일반 성장과 보상 경쟁은 분리. 유료 공격력/자동줍기/피로도 회복이 보상 경쟁의 점수·참가권을 늘리지 않게 함.
6. 제출판에서 유료 랜덤 보석, 자동 에어드랍, 대규모 신규 콘텐츠는 후순위. 무료 재화 뽑기도 확률 공개.

## 현재 기술적 경계

9/23 외부 APK 준비 확대: 사용자는 Railway 결제를 계속 보류하고, 기존 `mellowcat.xyz`와 분리된 지갑 identity 서브도메인을 선택했다. 제안 주소 `lumber.mellowcat.xyz`의 DNS/호스팅은 건드리지 않았다. Expo 기본 앱 아이콘 대신 새 도끼·나이테 아이콘을 별도 파일로 생성해 preview/production 앱 설정에 연결하고, 동일 아이콘을 제공할 정적 identity 사이트 빌더를 준비했다. Android JS 번들 export, 정적 사이트 빌드/해시 확인, 타입 검사, 자동 검사 153개 통과. 실제 HTTPS live 검사, EAS 계정/서명, 설치 가능한 APK 및 다른 기기 테스트는 미완료. 현재 환경의 프록시 때문에 기존 도메인 접근 여부는 판정하지 못했다.

9/23 외부 APK 사전 점검: preview API `/health`가 `preview` 모드와 지갑 identity origin을 돌려주고, `scripts/check-preview.mjs --live`가 HTTPS API/identity PNG를 읽기 전용으로 검증하도록 했다. 잘못된 로컬 API·도메인 불일치·아이콘 오류를 APK 빌드 전에 거부한다. 타입 검사와 자동 검사 153개 통과. 실제 공개 주소가 없으므로 live 검사는 아직 실행하지 않았고, EAS 계정/서명 키/외부 APK/호스팅 결제는 생성하지 않았다.

9/23 장착 후 100목재 안내: 개발 서버 계정에서 첫 기록 보상 수령·기념 도끼 장착·영구 +1 해금이 실제 DB에 반영됐고, 현재 신규 목재 0/100 퀘스트가 활성임을 읽기 전용으로 확인했다. 메인 퀘스트 단축 버튼에 최초 장착 이후 회수량을 `n/100`으로 표시하고 한/영 문구 및 경계 테스트를 추가했다. 타입 검사와 자동 검사 150개 통과. 에뮬레이터 접근성 덤프는 `could not get idle state`였으나, 사용자가 실제 화면에서 진행 표시가 잘 보인다고 확인했다. 서버 진행을 임의로 올리거나 저장을 초기화하지 않았다.

9/23 첫 기록 보상 UX: 당시 개발 서버 계정은 Lv.2 선행 조건과 finalized Devnet 첫 기록을 완료하고 `첫 기록 보상 수령` 단계에 있었다. 보상 버튼은 서버 작업 중 비활성화하고, 입력 큐·진행 중 요청·이미 수령한 상태에서 중복 명령을 막았다. 서버 확정 응답 후에만 한/영 수령 안내를 보여준다. 타입 검사와 자동 검사 150개 통과. 이후 사용자가 보상 수령·장착 화면을 확인했고 DB에서도 두 상태를 확인했다. 재실행·영문 화면 등 전체 실기기 QA는 남았다.

9/23 서버 고목 창 닫기: 고목 강화 또는 같은 등급 재생 요청이 입력 큐에 접수되면 창을 닫아 메인 화면으로 돌아가게 했다. 서버 요청이 거절되거나 실패하면 재화/레벨은 서버 확정 전까지 변경되지 않으며 기존 메인 안내에서 오류를 볼 수 있다. 로컬 저장 변경 없음. 타입 검사와 자동 검사 149개 통과. 기존 플레이를 소모하지 않기 위해 에뮬레이터에서 실제 재강화/재생 터치 검증은 아직 하지 않았다.

9/23 첫 지갑 퀘스트 코인: 서버 지갑 퀘스트 완료 시 코인 20개를 계정당 한 번 지급한다. 지급 기록은 서버 SQLite의 별도 테이블에 저장하며 진행/명령 영수증/경제 이벤트와 같은 트랜잭션에서 처리한다. 이미 지갑 퀘스트를 완료한 서버 계정은 퀘스트 창의 소급 수령 버튼으로 한 번만 받을 수 있다. 로컬 연습에는 지급하지 않는다. 자동 검사 149개와 타입 검사 통과, 기존 개발 DB 스키마 v4 적용 및 API 재시작 확인. 실제 앱 화면에서 수령 버튼/코인 변화의 확인은 남았다.

9/23 첫 수확 안내: 기존 하단 목재 안내 칸을 0/20부터 누적 수확 퀘스트 단축 버튼으로 바꾸고, 20개 달성 시 지갑 퀘스트로 연결한다. 서버에서는 회수 응답 확정 후에만 수집/완료 문구를 표시한다. 연습 진행이 있는 상태에서 별도 서버 저장으로 전환하려면 진행도 미이관을 확인받는다. 성장/재화 계산과 저장 규칙은 그대로다. 자동 검사와 타입 검사는 통과했고 에뮬레이터에서 진행 표시를 확인했으나 첫 20개→지갑 전환 실기기 QA는 남았다.

9/23 APK 빌드 프로필 준비: 내부 테스트용 별도 앱 ID와 dApp Store 제출용 원래 앱 ID를 `app.config.js`/`eas.json`으로 구분했다. 두 프로필 모두 APK 형식이고, 기존 로컬 Android release의 디버그 서명 산출물은 제출 금지로 명시했다. 실제 EAS 계정/서명 키/빌드/설치는 아직 하지 않았으며 공개 API·identity 도메인이 필요하다.

9/23 첫 플레이 안내 보완: `server-preview` 미로그인 화면을 로컬 연습으로 명시하고, 지갑 버튼이 서버 저장 로그인으로 이어지게 했다. 가이드에서 연습 저장과 서버 저장이 합쳐지지 않음을 안내하고 서버 미연결 기능을 구분한다. 실기기 표시/터치 및 외부 APK 테스트는 아직 필요하다.

9/23 Railway 준비: 결제를 미루기로 하고 API 실행 명령·헬스체크를 `railway.json`에 명시했다. Railway에서 볼륨 없이 또는 볼륨 밖 SQLite 경로로 시작하면 거부하도록 검사한다. 이는 로컬 설정/자동 검사 단계이며 Railway 서비스, 공개 API, 외부 APK를 만들었다는 뜻이 아니다. 결제는 외부 실기기 테스트 직전에 필요하다. 상세: `external-preview.md`.

9/20 외부 테스트 구성: 명시적 server-preview 모드, HTTPS API/지갑 identity 설정, 비개발 번들의 연결 메뉴, 서버의 별도 preview 바인딩 설정을 추가했다. 기본 loopback 동작 유지. 공개 배포/계정 생성/실제 APK 배포는 하지 않았으며 호스팅·도메인·서명/설치 방식 결정이 필요하다. `docs/external-preview.md` 참고. 현재 Android release는 개발 서명을 사용하므로 제출 APK로 취급하지 않는다.

9/23 재실행 보완: 지갑 로그인 토큰을 Expo SecureStore에 API 주소별로 보관하고 앱 재실행 시 서버 `/me`로 검증한 뒤 서버 진행을 불러오도록 연결했다. 만료·로그아웃 때 기기 토큰 삭제를 시도하고, 저장 실패 시 재서명이 필요하다고 안내한다. 개발 앱을 같은 Android 패키지로 재빌드·업데이트했고 기존 로컬 저장 파일 보존을 확인했다. 사용자는 자동 복구가 작동한다고 확인했고 에뮬레이터에서 서버 진행 화면을 다시 확인했다. 다만 로그아웃·만료·네트워크 실패의 실기기 QA는 아직 남았다. 앱 저장이 서버의 권위 있는 진행 데이터가 되지는 않는다.

9/23 퀘스트 접근성: 첫 수확 20개와 지갑 연결 이후에도 메인 화면의 하단 단축 버튼이 현재 퀘스트를 표시하고 퀘스트 창으로 연결되게 했다. 에뮬레이터 서버 계정에서 `도끼 레벨 2 달성` 표시와 버튼 이동을 확인했다. 이는 표시만 바꾸며 서버의 퀘스트 판정·보상은 변경하지 않는다. 첫 기록 거래 승인→보상→장착의 실제 지갑 QA는 남아 있다.

9/20 재접속 보완: 재로그인 시 기존 기록을 한 번 복구하고, 메뉴에 거래 재전송 없는 기록 상태 확인을 추가했다. 실제 HTTP 서버 재시작·RPC 장애·복구 테스트 포함 134개 검사/타입 검사 통과. 당시에는 지갑 승인 없는 상태 복구였고 토큰 영구 저장은 없었다. 실기기 QA는 여전히 남아 있다. 추가 콘텐츠로 확장하지 않았고, 다음 제출 게이트는 이 흐름의 실기기 QA 및 외부 테스트 APK/API 구성이다.
