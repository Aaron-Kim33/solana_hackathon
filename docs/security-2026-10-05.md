# Pre-submission security hardening — October 5

Local source changes; not a penetration-test certification. No production account reset,
payments, deletion of game saves, deployment or new EAS request was performed here.

- Auth endpoints receive separate process-local socket-address caps (30/minute) and
  a process-wide auth cap (120/minute). Forwarded headers are not trusted. A shared proxy
  can share a cap; this is not verified edge DDoS protection or per-human rate limiting.
- Auth challenges are capped at 3 outstanding per wallet and 2,000 overall. Already-issued
  signatures remain valid. Expired/used challenges and expired sessions are lazily cleaned
  at most once per minute on authentication traffic. Wallet links, progress, receipts,
  rewards and active sessions are untouched. Expiry indexes were added, without changing
  the game-store schema version or adding a periodic background job.
- brace-expansion was updated from 5.0.9 to 5.0.12 within the existing compatible dependency
  range. Only that lockfile package changed. Expo/React Native/MWA were not downgraded or
  force-upgraded. Other advisories remain; installed-package counts are not exploit counts.
- Android config blocks overlay, external shared-storage, camera and microphone permissions.
  Config tests pass; the final merged signed APK permissions must still be verified after
  rebuilding. Existing APKs retain their old permissions until updated.
- Support/privacy notice and submission field draft were added using the user-approved
  public email hi.mellowcat@gmail.com. Account deletion is manual, not an implemented
  self-service endpoint. No false fixed log-retention or backup guarantees are made.

Verified: 305 automated tests, TypeScript and Android JS export passed. Expo introspection
confirms `tools:node=remove` directives for all five blocked Android permissions, but is
not evidence of the final APK manifest merge. Audit now reports 18 high / 10 moderate
(28 package entries), down from 19 high / 10 moderate. No clean-security claim is made.
Phone gameplay QA of the October 3 build was reported successful by the user on October 5.
This does not certify optional Mainnet transaction QA, backup restore or attack resilience.
